## 项目经历

### 企业级知识库智能问答系统（RAG） ｜ 个人全栈项目 ｜ 2026.06 – 2026.09

**技术栈**：Python / FastAPI / LangChain / ChromaDB / BM25 / Rerank / Redis / MySQL / Vue3 / TypeScript / Docker

**项目简介**：面向企业多部门知识空间的权限化智能问答系统。支持 TXT、PDF、DOCX、XLSX 文档入库与结构化分块，提供混合检索问答、引用溯源、拒答兜底，以及员工/客服/管理员三角色的权限管理与量化评测闭环。

- **检索精度**：通过「向量召回 + BM25 关键词召回 → RRF 排名融合 → Rerank 精排」的混合检索架构，解决了单一向量检索对型号、数字等精确关键词失真、深层文档细节召回不全的问题，使答案要点覆盖与引用准确性大幅提升
- **效果量化**：通过自建 60 题三角色评测集 + LLM-as-Judge 自动评分，解决了 RAG 优化"凭感觉、无数据"的问题——量化系统加权准确率至 82.5%，并经错误归因定位"精排截断导致多要点覆盖不足"的检索瓶颈，修复后同套评测复测验证，形成评测驱动的迭代闭环
- **多轮对话**：通过"规则前置检测指代词 + 仅追问场景触发 LLM 改写"的 Query 改写策略，解决了多轮对话中"它/这个"等指代不明导致检索偏移的问题，同时避免了每轮调用 LLM 改写的额外 Token 成本
- **分块与溯源**：通过按文档类型（章节/问答对/条目）自适应分块并让子分片继承章节标题、问题文本等元数据，解决了固定长度切分割裂语义、回答无法溯源到原始章节的问题
- **幻觉抑制**：通过基于 Rerank 相关性分数的可答性判断 + 标准拒答话术兜底，解决了低相关检索结果诱导大模型编造答案的问题，保证无据可查时系统"宁可拒答、不可胡答"
- **权限安全**：通过"JWT 仅存用户 ID + 每请求回库校验角色状态、FastAPI 依赖注入的接口级 RBAC、检索层知识空间过滤"三层纵深防御，解决了前后端分离后 UI 隐藏可被接口绕过、令牌携带角色导致权限变更后残留越权的问题；通过 Redis 令牌黑名单（TTL=令牌剩余寿命）解决了 JWT 签发后无法主动吊销的问题
- **高并发与稳定性**：通过 Redis 实现热点数据缓存（写失效策略）、IP+账号双维度滑动窗口限流（429 + Retry-After）与异步索引任务状态机，解决了列表重复计算、接口滥用刷量、后台文档索引进度不可追踪的问题；通过"安全控制 fail-closed、可用性功能 fail-soft"的分级降级设计，解决了 Redis 故障时安全性与服务可用性不可兼得的问题
- **工程化交付**：通过 Docker Compose + Nginx 一键部署与 SQLite→MySQL 迁移脚本，解决了环境不一致与数据层并发瓶颈问题；通过 20 个 pytest 用例覆盖鉴权、限流、缓存、任务全链路，解决了核心功能迭代中的回归风险问题
