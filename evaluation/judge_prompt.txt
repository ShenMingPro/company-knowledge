你是专业的答案评测裁判，需要逐个要点判断模型回答的覆盖情况。

### 评测任务
用户问题：{question}

标准答案关键要点：
{key_points}

模型回答：
{model_answer}

### 评测要求
1. **逐要点判断**：对每个关键要点独立判断，返回其状态和证据
2. **状态定义**：
   - covered: 模型回答中明确覆盖了该要点，且有具体证据支持
   - missing: 模型回答中未提及该要点
   - contradicted: 模型回答与该要点存在明显矛盾或事实错误

3. **判断原则**：
   - 不因措辞不同判错（如"提前30天"和"需提前一个月"是等价的）
   - 不把缺失一个后续步骤直接判为 wrong，单个要点缺失应标记为 missing
   - 不自行增加标准答案中不存在的要求
   - 如果模型回答中有该要点的具体内容，必须摘录为证据片段

4. **证据要求**：
   - covered 状态必须提供证据片段，直接从模型回答中摘录
   - 证据片段应包含关键信息（数字、期限、条件、步骤等）
   - 没有证据支持的 covered 将被降级处理

5. **特殊情况处理**：
   - 如果模型完全拒答或答非所问，所有要点标记为 missing
   - 如果模型部分回答，只标记实际覆盖的要点为 covered
   - 流程类问题：模型只答出前几步时，后续步骤标记为 missing，不是 wrong

### 输出格式
严格返回 JSON 格式，包含 key_points_result 数组。

JSON 格式示例（不要包含 ```json 标记）：
{{
  "key_points_result": [
    {{
      "key_point": "关键要点原文",
      "status": "covered/missing/contradicted",
      "evidence": "从模型回答中摘录的证据片段，如果是 missing 或无证据则为空字符串"
    }}
  ]
}}

关键要点：

2. 试用期离职提前3天通知
3. 在OA系统提交离职申请

模型回答：正式员工需要提前30天书面通知公司，试用期员工提前3天即可。需要在OA系统提交离职申请。

      "evidence": "需要在OA系统提交离职申请"
    }}}}
  ]
}}}}

现在请对上述任务进行评测，返回 JSON 格式结果。
